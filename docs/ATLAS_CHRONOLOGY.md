# Atlas calendar range filter

The atlas has a recent and an ancient handle on a descending, deliberately non-linear timeline: now, 1000 CE, beginning of the era, 1000–8000 BCE in millennial steps, then 18000, 28000, 48000, 98000, 198000, 498000 BCE and an unbounded older edge. The current year comes from the browser clock; shared `dateTo=now` retains that dynamic meaning. Zero is a UI boundary labeled “بداية الميلاد”, not a claim of a historical year zero. Native keyboard-accessible range inputs and equivalent labeled dropdowns support pointer, touch and assistive input.

The default full span does not filter records, including undated records. In an active span, undated records are excluded unless explicitly included. A range intersects inclusively when `sampleEnd >= selectedOldest` and `sampleStart <= selectedNewest`. A record crossing either selected boundary appears once, with a partial-overlap label. Map points, site counts, record counts and exports use the same filtered records. No dates or classifications in the data are overwritten.

Evidence priority: the original reported calendar range/year (`ageText`, retained dateEvidence), then a supplemental AADR calendar date only if the original text is absent. Where no calendar interval is available, a reported mean BP is represented by a single approximate point using its documented baseline (1950 by default), clearly labeled. This approximation is not radiocarbon calibration and does not invent an uncertainty interval. Raw laboratory BP ± error and free-form approximate prose are not parsed as calendar ranges. Published conventional radiocarbon measurements are preserved untouched.

Calendar ranges across BCE/CE, reversed source endpoint order, calibrated source labels, en/em dashes and explicit Arabic BCE wording are supported. Dates that cannot be parsed and have no mean remain undated. Existing advanced mean-BP controls and legacy shared links retain their existing, additional mean-only restrictions.

Shared URLs store `dateFrom` (signed calendar bound, or `old`), `dateTo` (signed calendar bound, or `now`) and optional `dateUnknown=1`. Invalid and inverted ranges are rejected; exact bounds from a shared URL are preserved without silently snapping. Guest search allowance counts a committed selection, not each drag preview. Global reset and the date-only reset restore all periods.

Validation: `node --test tests/atlas-chronology.cjs` covers the agreed 3100–2900 BCE boundary example in both periods, inclusive endpoints, BCE/CE distinction, cross-era source ranges, source precedence, unknown dates, BP fallback, unbounded old dates, non-duplication, slider change events, reset and URL restore. This is a search rule over reported evidence, not a new archaeological period classification.
