# Sample IDs inside the two tree diagrams

The separate flat sample list remains removed. Public sample identifiers are now rendered as connected leaves of their reported/resolved node in both the side explorer and the selected vertical subtree. Opening a branch reveals its subbranches and directly placed sample leaves. Each sample is attached once, not repeated at every ancestor. Eight sample IDs are rendered at a time per node; a labeled “more sample IDs” button exposes subsequent batches without silently discarding records.

Display uses `sampleId`, then `geneticId`, then the record ID. Person names and display names are not rendered. Source-confirmed Big Y/WGS samples are distinguished from confirmed non-developed results; test panel size alone never confirms a branch. Prediction status always overrides a declared advanced test, remains red and explicitly unconfirmed, and is attributed to the source or LX only when the record establishes that origin. At implementation time the public project manifest contains source predictions and zero newly published LX predictions; the UI does not invent them.

Ancient samples retain the remains icon. Living samples retain the living icon with developed/non-developed labels. Predicted leaves have a red icon treatment and red border with an explicit unconfirmed label. Icons are accompanied by text, not color alone. Information dialogs show only the public ID, reported call, stated test type, evidence state and a source/atlas link. A green source call is not relabeled as a BAM result analyzed by LX.

The source tree resolver supplies placement. Ancestor-supported placements remain marked “detailed branch unresolved” on the visible leaf; they are not promoted to exact terminal matches. Unplaced records remain unattached and their number is visible beneath the main tree. For the current pinned Y snapshot plus project records, 659 records have no primary placement; this is a known reference limitation, not a reason to fabricate branches. Different source-tree releases and records may change that count.

Main-tree leaves and counts use the available full snapshot. The lower selected subtree and leaves use the active search/filter result. Existing SNP evidence, identifiers, import deduplication and chronological data are not overwritten. Sample leaves do not count as genetic child branches.

Checks: `tests/tree-samples.cjs` covers identity labels, confirmation versus declared test, source/LX predictions, no ancestor duplication and ancestor-supported warnings. Existing research integration tests verify unchanged node/alias placement. Browser checks must cover an ancient leaf, developed and non-developed living leaves, red prediction leaves, pagination, both orientations, and the preserved compact cards/age information.
