Getting access

The public landing page identifies services in preparation. My Samples requires an account and enabled access. Project-reference management is a separate restricted tool; being a testing-company project administrator does not automatically grant LX administration.

Before saving, provide kit ID, testing provider and country and confirm authorisation for private processing. Read the processing terms. Names are optional and private; record control is not proof of genetic ownership.

Preparing an individual file or row

  1. Use an export available in your testing account’s Y-STR results, or request a file from your project administrator. Preserve original marker names and values. A results-page URL is not an analysis file.
  2. Save one table as CSV or TSV. Export the relevant worksheet from Excel or Google Sheets. Do not submit PDF, images or HTML to the STR input.
  3. Upload a file or paste marker headers together with your row. For a multi-kit table, enter your exact kit ID; it must resolve to exactly one row.
  4. Do not delete missing cells or reorder unnamed values. Review the parsed sample before analysis; correct rejected input in the original file.

The STR file limit is 100KB. Format example only: DYS393=13, then DYS390=24 on another line; this alone is insufficient for prediction.

Unnamed values and missing loci

Prefer named markers. For numbers-only input, select the correct FTDNA 12/25/37/67/111 panel and grouped or expanded multi-copy layout. Do not assume another provider uses FTDNA order.

Panel 12 alone does not meet the current comparable-locus minimum. Missing values are not zero. Microvariants are retained and reported as excluded from integer step-distance comparison, never silently rounded.

Only supply a previously confirmed SNP ancestor after checking it. It constrains comparison but does not confirm the predicted terminal branch.

Project tables and references

Only authorised administrators can load comparison references. Obtain permission first; a public table does not automatically permit republishing names or markers.

  1. Prepare CSV/TSV with one header and one row per kit, including kitId, haplogroup, snpVerified and marker columns.
  2. In reference management, enter source title, URL, version and date, then choose the file. A downloadable template avoids manual JSON editing.
  3. Set snpVerified=true only after reviewing SNP-confirmation evidence. A branch label or “Big Y” text alone is not independent verification.
  4. Analyse the selected kit by ID. Reference import does not automatically analyse, save or publish every project member.

Conflicting duplicate IDs are excluded from comparison. Different IDs belonging to one person require evidence reconciliation, not name similarity alone.

Prediction method and limitations

This is an experimental LX comparison method, not a government-approved model or an established accuracy claim. It compares STR profiles with SNP-confirmed references, normalises locus names and multi-copy values, and treats DYS389II as the segment independent of DYS389I to avoid double counting.

Paths come from the selected reference tree. Conflicting or unresolved references are excluded, as is the target itself when its kit ID is supplied. Ranking uses nearest references and genuinely shared loci, stopping when coverage or evidence is insufficient. At least 12 comparable loci are required; that is a computational threshold, not an accuracy guarantee.

The original voting denominator is retained during descent so dissenting or shorter paths cannot artificially inflate support. Support is not a calibrated probability or evidence of kinship, tribe, ethnicity or paternity.

STR predictions do not override confirmed SNP results or reanalyse sequence data. Independent SNP-confirmed evaluation is required before a scientific accuracy claim; software tests do not measure biological accuracy.

Reports and saving

A smaller distance means greater similarity at shared loci. Distances based on different overlap are not directly equivalent. Alternatives summarise nearby references, not all branches or population frequencies. Expand the audit for sources, versions and exclusions.

Predict and save stores a private result only after analysis and upload succeed. Wait for confirmation; a prediction alone does not prove persistence. Download the available report and review My Samples. Automatic tree publication is not enabled.

RAW and evidence files

For autosomal RAW, use the unzipped original TXT/CSV/TSV up to 20MB, with rsid, chromosome, position and genotype fields. Only parsing and quality reporting are available; ancestry, traits and health analysis are not enabled. Autosomal analysis is separate from Y/mt trees.

Evidence upload supports the formats listed in the tool, including BAM, VCF and PDF, up to 20MB. Files are stored for review; uploading does not automatically analyse sequence or verify an assignment. Do not rename a large file to bypass the limit. A source URL is a citation, not direct import.

Privacy, corrections and help

Names, files and reports remain private according to record delegation and access controls. Email is hidden by default. Files are not automatically used for training. Consult processing terms for details.

Request country/location/flag corrections from the sample record with the proposed value, reason and evidence. The site owner reviews the request and the decision is logged; flags follow the accepted country.

For rejected files, check the message, kit ID, marker headers, copy counts and size. Insufficient references may legitimately produce an unresolved result; do not force a branch by changing input. Use LXHAZZAA support for assistance.

Input-format sources

FTDNA panel formatting follows the company’s learning-centre results table. NIST STRBase is a government reference for Y-STR nomenclature. Format documentation is not endorsement or validation of the LX predictor.
